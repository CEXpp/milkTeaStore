# 2 数据库详细设计

本章将 HLD 第 4 章的概念模型落为可执行的建表脚本：13 张表的完整 DDL、索引与约束、Flyway 迁移规划。字段与索引为强约束。

<a id="_Toc100009"></a>

## 2.1 设计总则

- 命名：表与字段一律 snake_case，表名 = 领域前缀 + 实体（如 order_item）。MyBatis-Plus 驼峰映射自动对应。
- 金额：DECIMAL(10,2)，Java 侧 BigDecimal，比较与求和禁止 double。
- 时间：DATETIME，库内统一东八区，由应用层写入。
- 主键：BIGINT 自增（单店量级足够，无需分布式 ID）。
- 软删除：不做。订单作废走状态字段（VOIDED），商品下架走 status 字段，数据永不物理删除——统计需要完整历史。
- 快照原则：订单与订单项在创建时固化商品名、价格、规格选择的副本，后续改价改名不影响历史订单与统计。

## 2.3 完整建表 SQL（Flyway V1）

以下为 Flyway 首版迁移脚本全文（V1__init_schema.sql）。后续任何表结构变更新增 Vn 脚本，禁止修改历史脚本。

**`V1__init_schema.sql（1/2：账号、顾客、商品与规格）`**

```sql
CREATE TABLE admin_user (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(64)  NOT NULL,
  password_hash VARCHAR(128) NOT NULL COMMENT 'BCrypt',
  nickname      VARCHAR(64)  NOT NULL DEFAULT '店长',
  created_at    DATETIME     NOT NULL,
  updated_at    DATETIME     NOT NULL,
  UNIQUE KEY uk_username (username)
) COMMENT '商家账号（单账号）';

CREATE TABLE customer (
  id             BIGINT AUTO_INCREMENT PRIMARY KEY,
  openid         VARCHAR(64)  NOT NULL COMMENT '微信 openid',
  nickname       VARCHAR(64)  NULL COMMENT '昵称（可选授权）',
  created_at     DATETIME     NOT NULL,
  last_active_at DATETIME     NOT NULL,
  UNIQUE KEY uk_openid (openid)
) COMMENT '顾客（静默登录标识）';

CREATE TABLE category (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  name       VARCHAR(32) NOT NULL,
  sort_order INT         NOT NULL DEFAULT 0,
  created_at DATETIME    NOT NULL,
  UNIQUE KEY uk_name (name)
) COMMENT '商品分类';

CREATE TABLE spec_group (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  code         VARCHAR(32)  NOT NULL COMMENT 'CUP_SIZE/TEMPERATURE/SWEETNESS/TOPPING',
  name         VARCHAR(32)  NOT NULL COMMENT '杯型/温度/甜度/加料',
  multi_select TINYINT      NOT NULL DEFAULT 0 COMMENT '0 单选 1 多选（加料=1）',
  enabled      TINYINT      NOT NULL DEFAULT 1,
  sort_order   INT          NOT NULL DEFAULT 0
) COMMENT '全局规格组模板';

CREATE TABLE spec_option (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  group_id    BIGINT       NOT NULL,
  name        VARCHAR(32)  NOT NULL COMMENT '中杯/大杯/少冰/半糖/珍珠...',
  price_delta DECIMAL(10,2) NOT NULL DEFAULT 0.00 COMMENT '价差（杯型/加料计价，其余 0）',
  enabled     TINYINT      NOT NULL DEFAULT 1,
  sort_order  INT          NOT NULL DEFAULT 0,
  KEY idx_group (group_id)
) COMMENT '规格项';

CREATE TABLE product (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  category_id  BIGINT        NOT NULL,
  name         VARCHAR(64)   NOT NULL,
  description  VARCHAR(255)  NULL,
  image_key    VARCHAR(255)  NULL COMMENT 'MinIO 对象 key（非完整 URL）',
  base_price   DECIMAL(10,2) NOT NULL,
  status       TINYINT       NOT NULL DEFAULT 1 COMMENT '1 上架 0 下架',
  sort_order   INT           NOT NULL DEFAULT 0,
  created_at   DATETIME      NOT NULL,
  updated_at   DATETIME      NOT NULL,
  KEY idx_category (category_id),
  KEY idx_status (status)
) COMMENT '商品';

CREATE TABLE product_spec_group (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  product_id BIGINT NOT NULL,
  group_id   BIGINT NOT NULL,
  UNIQUE KEY uk_product_group (product_id, group_id)
) COMMENT '商品适用的规格组（默认全部勾选）';
```

```sql
CREATE TABLE orders (
  id             BIGINT AUTO_INCREMENT PRIMARY KEY,
  order_no       VARCHAR(32)   NOT NULL COMMENT 'yyMMdd+5位序列',
  source         VARCHAR(16)   NOT NULL COMMENT 'MINI_PROGRAM / AI / COUNTER',
  status         VARCHAR(16)   NOT NULL COMMENT 'PENDING_PAYMENT/PAID/PREPARING/COMPLETED/CLOSED/VOIDED',
  customer_id    BIGINT        NULL COMMENT '柜台单为 NULL',
  pay_channel    VARCHAR(16)   NULL COMMENT 'MOCK / WECHAT（预留）',
  transaction_id VARCHAR(64)   NULL COMMENT '支付流水号（Mock 生成 / 微信预留）',
  total_amount   DECIMAL(10,2) NOT NULL COMMENT '应付总额（快照）',
  pickup_code    VARCHAR(8)    NULL COMMENT '取餐码（进入 PAID 时分配）',
  remark         VARCHAR(255)  NULL COMMENT '口味备注',
  paid_at        DATETIME      NULL,
  started_at     DATETIME      NULL COMMENT '开始制作时间',
  completed_at   DATETIME      NULL COMMENT '出餐时间',
  closed_at      DATETIME      NULL COMMENT '超时关闭时间',
  voided_at      DATETIME      NULL,
  void_reason    VARCHAR(255)  NULL,
  created_at     DATETIME      NOT NULL,
  updated_at     DATETIME      NOT NULL,
  UNIQUE KEY uk_order_no (order_no),
  KEY idx_status_created (status, created_at),
  KEY idx_customer (customer_id, created_at),
  KEY idx_pickup_date (pickup_code, paid_at)
) COMMENT '订单';

CREATE TABLE order_item (
  id               BIGINT AUTO_INCREMENT PRIMARY KEY,
  order_id         BIGINT        NOT NULL,
  product_id       BIGINT        NOT NULL COMMENT '关联商品（统计排行用）',
  product_name     VARCHAR(64)   NOT NULL COMMENT '快照',
  base_price       DECIMAL(10,2) NOT NULL COMMENT '快照基础价',
  options_snapshot JSON          NULL COMMENT '[{group,option,delta}] 快照',
  quantity         INT           NOT NULL DEFAULT 1,
  unit_price       DECIMAL(10,2) NOT NULL COMMENT '快照单价=基础价+Σ价差',
  item_amount      DECIMAL(10,2) NOT NULL COMMENT 'unit_price*quantity',
  KEY idx_order (order_id),
  KEY idx_product (product_id)
) COMMENT '订单项（快照）';

CREATE TABLE ai_session (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_uuid VARCHAR(64)  NOT NULL,
  customer_id  BIGINT       NOT NULL,
  draft_items  JSON         NULL COMMENT '草稿单 [{productName,optionNames[],quantity}]',
  expires_at   DATETIME     NOT NULL COMMENT '30 分钟无活动过期',
  created_at   DATETIME     NOT NULL,
  updated_at   DATETIME     NOT NULL,
  UNIQUE KEY uk_uuid (session_uuid),
  KEY idx_customer (customer_id),
  KEY idx_expires (expires_at)
) COMMENT 'AI 会话（含草稿单）';

CREATE TABLE ai_message (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id BIGINT      NOT NULL,
  role       VARCHAR(16) NOT NULL COMMENT 'USER / ASSISTANT / TOOL',
  content    TEXT        NOT NULL,
  created_at DATETIME    NOT NULL,
  KEY idx_session (session_id, id)
) COMMENT 'AI 会话消息历史';

CREATE TABLE shop_config (
  id           BIGINT AUTO_INCREMENT PRIMARY KEY,
  config_key   VARCHAR(64)  NOT NULL,
  config_value VARCHAR(255) NOT NULL,
  UNIQUE KEY uk_key (config_key)
) COMMENT '门店配置 KV（paused 等）';

CREATE TABLE daily_seq (
  id         BIGINT AUTO_INCREMENT PRIMARY KEY,
  seq_date   DATE         NOT NULL,
  seq_type   VARCHAR(16)  NOT NULL COMMENT 'ORDER_NO / PICKUP_CODE',
  current_seq INT         NOT NULL DEFAULT 0,
  UNIQUE KEY uk_date_type (seq_date, seq_type)
) COMMENT '每日流水（订单号/取餐码，行锁递增）';
```

## 2.4 关键设计说明

- orders.pickup_code 为 VARCHAR(8)：当日 001 起三位递增，超过 999 自然进位为四位；每自然日重置（daily_seq 按日期行）。
- order_item.options_snapshot 用 JSON 列而非子表：快照数据只读不作查询条件，JSON 足够；统计排行按 product_id 聚合，不依赖 JSON 内部字段。
- ai_session.draft_items 同理存 JSON：草稿单是会话内临时结构，支付前即转正式订单（orders + order_item）。
- daily_seq 行锁方案：UPDATE daily_seq SET current_seq=current_seq+1 WHERE seq_date=? AND seq_type=? 后 SELECT，同事务内完成；单店并发下足够，不引入 Redis。

# 3 API 详细设计

三端全量契约：统一规范、错误码、约 33 个端点的字段级定义。端点路径与响应结构为强约束，开发不得变更。

<a id="_Toc100015"></a>

## 3.1 统一规范

所有接口返回统一响应体；字段名与路径为强约束，执行 AI 不得变更：

```json
{
  "code": 0,            // 0=成功，非 0=业务错误码（见 3.2）
  "message": "ok",     // 人类可读信息（错误时可直接展示给用户）
  "data": { ... }       // 业务数据（错误时可为 null）
}
```

- 鉴权：Authorization: Bearer <JWT>。分体系鉴权路径矩阵见 HLD 5.1（本文档各端点标注沿用）。
- 分页参数：page（从 1 起）、size（默认 20，最大 100）；分页响应固定 {list, total, page, size}。
- 时间格式：yyyy-MM-dd HH:mm:ss 字符串。
- 金额：字符串形式的两位小数（如 "12.00"），避免前端浮点精度问题。

<a id="_Toc100016"></a>

## 3.2 错误码表

| code | 含义 | 触发场景 |
|---|---|---|
| 0 | 成功 | — |
| 401 | 未登录或令牌过期 | JWT 缺失/过期/伪造 |
| 403 | 无权限 | 顾客令牌访问 admin 路径等 |
| 1001 | 参数错误 | 字段缺失、格式非法、数量超限 |

# 4 订单域详细设计

<a id="_Toc100026"></a>

## 4.1 状态机定义与迁移校验

状态枚举 OrderStatus：PENDING_PAYMENT（待支付）、PAID（已支付待制作）、PREPARING（制作中）、COMPLETED（已完成）、CLOSED（超时关闭）、VOIDED（已作废）。合法迁移在 OrderService 内以静态迁移表硬编码，任何越界迁移抛 BusinessException(1004)：

| 当前状态 | 事件 | 触发方 | 目标状态 | 伴随动作 |
|---|---|---|---|---|
| PENDING_PAYMENT | 支付成功 | 顾客（pay 接口） | PAID | 分配取餐码、写 paid_at、pay_channel、transaction_id |
| PENDING_PAYMENT | 15 分钟超时 | 后端定时任务 | CLOSED | 写 closed_at；不回收取餐码（未分配） |
| PAID | 开始制作 | 商家（start） | PREPARING | 写 started_at |
| PAID | 作废 | 商家（void） | VOIDED | 写 voided_at、void_reason；退款额进统计 |
| PREPARING | 出餐完成 | 商家（complete） | COMPLETED | 写 completed_at |
| COMPLETED / CLOSED / VOIDED | — | — | （终态） | 终态不可迁移 |

## 4.2 取餐码与订单号流水

- 取餐码：daily_seq 表（seq_type=PICKUP_CODE）行锁递增。进入 PAID 的瞬间（支付成功或柜台单创建时）分配，格式为去除前导零的三位字符串（“001”至“999”，超限自然进位四位）。
- 订单号：daily_seq 表（seq_type=ORDER_NO），格式 yyMMdd + 5 位序列，如 26091200123。
- 并发安全：UPDATE daily_seq SET current_seq = current_seq + 1 WHERE seq_date = ? AND seq_type = ? 影响行数为 0 时 INSERT 新行后重试（一次），全程在创建订单/支付事务内。
- 每日重置：seq_date 维度天然按自然日重开新行，无需定时任务。

<a id="_Toc100028"></a>

## 4.3 超时关单调度

**`OrderCloseScheduler（order 域）`**

```java
@Scheduled(fixedDelay = 60_000)   // 每 60 秒
public void closeExpiredOrders() {
    // 条件更新防并发：只关仍是 PENDING_PAYMENT 的单
    int closed = orderMapper.updateStatusIfPending(
        OrderStatus.PENDING_PAYMENT, OrderStatus.CLOSED,
        LocalDateTime.now().minusMinutes(15));
    if (closed > 0) log.info("auto-closed {} expired orders", closed);
}
```

- 应用启动类加 @EnableScheduling；时间阈值 15 分钟来自配置项 order.payment-timeout-minutes。
- 轮询接口天然反映状态变化，关单后顾客端 active 列表自动消失该单（前端显示“订单已超时关闭”提示后从列表移除）。

<a id="_Toc100029"></a>

## 4.4 轮询机制

- 顾客端：进行中订单页每 3 秒 GET /orders/{id}/status（轻量响应）；订单进入 COMPLETED 后停止轮询并展示取餐成功态。
- 商家端：看板页每 3 秒 GET /admin/orders/board 全量刷新；前端对比 pending 列表 orderId 集合，出现新 id 时播放提示音并高亮该行。
- 轮询参数（间隔）为前端常量；升级 WebSocket 时后端加推送服务、前端换监听，接口保留作为降级通道。

<a id="_Toc100030"></a>

## 4.5 下单价格计算（唯一入口）

无论小程序购物车、柜台单还是 AI 草稿转订单，价格计算收敛到 OrderDomainService.calculatePrice(items)：读取商品当前 base_price + 逐项校验规格组合合法性 + 累加价差 × 数量。该方法是价格的唯一事实来源，三个入口共用——这正是 SRS「约束三原则」中「价格一律后端计算」的落地。

**`计算规则（伪代码）`**

```text
unitPrice = product.basePrice + Σ(option.priceDelta)
itemAmount = unitPrice × quantity
totalAmount = Σ(itemAmount)              // 无优惠体系，无抹零
校验：单选组恰选 1 项（required 组）；多选组 0..n 项；
      option 必属于该商品勾选的 specGroup；商品必须 status=1
```

- pay 接口流程：查单（校验归属与状态）→ shop 暂停校验（已支付单不受影响）→ provider.pay() → 成功则同事务内：更新状态 PENDING_PAYMENT→PAID、分配取餐码、写支付字段。
- provider 选择：配置项 payment.active-channel=mock（真店切 wechat 时新增 WechatPaymentProvider 实现并改配置，调用方代码零改动）。
- 微信支付预留：orders 表 pay_channel/transaction_id 字段已就位；回调入口设计为 payment 域的独立 Controller（/api/payment/callback/{channel}），Mock 不启用。

## 6.3 工具集设计（@Tool 签名）

四个工具全部返回 String（给模型看的反馈文本），副作用作用于草稿单（ai_session.draft_items）。支付动作不设工具——AI 永远不能替用户付钱：

**`PointOfSaleTools（ai 域）`**

```java
@Tool("查询当前在售菜单：商品名、价格、可选杯型温度甜度加料。找商品必用。")
String searchMenu(@ToolParam("搜索关键词，可空") String keyword) { ... }

@Tool("增改草稿单：按商品名与选项名写入/覆盖/追加购物草稿。")
String updateDraftOrder(
        @ToolParam("商品名") String productName,
        @ToolParam("选项名列表，如 [大杯,少冰,五分糖,珍珠]") List<String> optionNames,
        @ToolParam("数量，默认 1") int quantity) { ... }

@Tool("清空草稿单。用户说不要了/重新点时使用。")
String clearDraftOrder() { ... }

@Tool("查看当前草稿单内容。")
String getDraftOrder() { ... }
```

工具内部实现的校验即约束三原则的执行点：

- updateDraftOrder 按名称精确匹配商品（LIKE 兜底），匹配不到返回“未找到该商品”文本——模型据此向顾客道歉并推荐，无法下单不存在的商品。
- 选项名匹配 spec_option；单选组选项缺失时返回“该商品需要选择杯型”——模型据此追问顾客。
- 价格由 calculatePrice（4.5 节唯一入口）计算写草稿；模型输入中不存在任何价格字段。
- 商品下架（status=0）在 searchMenu 结果中即不可见，updateDraftOrder 亦拒绝。

**`PointSalePrompt（常量，全文如下）`**

## 6.5 会话与记忆管理

- AiServices 装配 ChatMemory = MessageWindowChatMemory(maxMessages=20)，@MemoryId 绑定 session_uuid；自定义 ChatMemoryStore 将消息读写映射到 ai_message 表（role: USER/ASSISTANT/TOOL）。
- 会话生命周期：chat 请求携带 sessionId（首轮空则新建）→ 每次对话刷新 expires_at = now + 30 分钟 → 过期会话由 @Scheduled 每分钟惰性清理（复用 4.3 模式，超期会话草稿作废）。
- maxMessages 与超时均为配置项（ai.max-messages / ai.session-timeout-minutes），需求侧口径：保留最近 10 轮、30 分钟清空。

<a id="_Toc100040"></a>

## 6.6 chat 接口实现流程（含降级）

| 步骤 | 动作 | 异常分支 |
|---|---|---|
| 1 | 鉴权取 customerId；定位/新建会话 | 会话过期则新建并提示重新点单 |
| 2 | assistant.chat(message, sessionId) 调 LangChain4j（模型自动多轮工具调用） | 超时/HTTP 错误 → 捕获返回 code=1008 + fallbackText |
| 3 | 读取 ai_session.draft_items；非空则组装 CARD 响应（draft + calculatePrice 结果），否则 TEXT | — |
| 4 | 落库本次 USER/ASSISTANT 消息；刷新 expires_at | — |

- confirm-order：草稿非空校验 → OrderService.createOrder（复用 4.5 唯一价格入口与校验）→ 清空草稿 → 返回 orderId 供前端连发 pay。
- AI 出错不影响主流程：菜单点单、柜台点单全程不经过 ai 域。

# 9 安全详细设计

本章落实 HLD 9.1：鉴权过滤器、AI 防护分层、上传校验与文件存储策略。

<a id="_Toc100051"></a>

## 9.1 鉴权实现

- JWT 库：jjwt（HS256，密钥 jwt.secret 配置项，长度≥32 字符）。
- 过滤器：JwtAuthenticationFilter 按 HLD 5.1 路径矩阵分派——/api/admin/** 校验 admin 令牌（claims.role=admin）；/api/customer/** 默认校验顾客令牌，白名单路径放行。
- 密码：BCrypt 存 admin_user.password_hash；登录失败连续 5 次锁定 10 分钟（内存计数即可）。
- 订单归属：顾客端订单类接口一律校验 orders.customer_id = 当前 customerId，否则 1005。

<a id="_Toc100052"></a>

## 9.2 AI 注入与滥用防护

- 提示词注入：系统提示词已限定角色与工具边界；工具输入全部经过名称→数据库实体匹配（参数化 SQL），恶意文本无法直达执行层——编造的商品名匹配不到即拒单。
- 金额不可操纵：模型请求体中不存在价格字段；草稿单金额由后端 calculatePrice 生成。
- 频率限制：chat 接口按顾客维度简单限流（每分钟 10 次，内存滑动窗口），防刷免费模型额度。
- Mock 支付仅在练手形态启用：payment.active-channel=mock 仅存在于开发/演示配置，真店配置文件切 wechat。

<a id="_Toc100053"></a>

## 9.3 上传与内容安全

- 类型白名单 jpg/png/webp（魔数校验，不信扩展名）；单张 ≤ 2MB；key 由后端生成（用户输入不参与路径，杜绝路径穿越）。
- /api/files/{key} 校验 key 正则 ^[a-z0-9/-]+\.(jpg|png|webp)$ 后取流，非白名单直接 404。

<a id="_Toc100054"></a>

## 9.4 文件存储与 URL 策略（MinIO）

<a id="_Toc100055"></a>

## 9.4.1 容器与桶

- MinIO 以 compose 容器运行（见 10.1），端口 9000（API）/9001（控制台），数据卷持久化；bucket 由 backend 启动时不存在则自动创建（名称 milk-tea，公开读由代理接口替代，桶策略保持私有）。
- SDK：minio-java 8.x；MinioClient 以 minio.endpoint/minio.access-key/minio.secret-key 配置装配。
- key 规则：menu/{yyyy}/{MM}/{uuid}.{ext}——菜单图片专用前缀，便于未来按前缀清理或迁移 OSS。

<a id="_Toc100056"></a>

## 9.4.2 URL 策略（穿透域名变化免疫）

数据库只存 key；对外暴露一律走后端代理 /api/files/{key}（从 MinIO 取流转发 + 1 天缓存头）。因此 cpolar 域名变化只需前端改请求基地址，历史数据零迁移。真店迁 OSS：替换 FileStorageService 实现（接口 put/get），key 规则不变。

**`存储抽象（file 域）`**

```java
public interface FileStorageService {
    String put(InputStream in, long size, String key);   // 存 MinIO
    InputStream get(String key);                          // 取流（代理接口用）
}
```
